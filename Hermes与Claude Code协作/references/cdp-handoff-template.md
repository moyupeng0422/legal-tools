# CDP 保活交接模板：SSH CC → 本地桌面 CC

当 SSH CC 完成 CDP 保活的开发和验证后，将长期保活交给用户本地桌面 CC 接管的标准流程。

## 触发条件

- CDP 保活已在 SSH CC 下跑通（≥3 轮验证通过）
- 用户要求长期运行，但 SSH CC 依赖 tmux session 无法持久

## 交接操作

### 1. Hermes 向 SSH CC 发停止指令

```
任务交接：{系统名} CDP 保活已转给用户本地桌面 CC 接管。
你这边可以停掉后台保活进程 {task_id}，杀掉所有 auto_refresh 进程。
辛苦了，{N}轮测试全部通过，数据很有价值。
```

确认 SSH CC 完成清理（后台任务停止、进程终止）。

### 2. 给用户本地 CC 的完整指令模板

```
当前项目：{login-helper 项目绝对路径}

背景：{系统名} 已接入 CDP 保活。Edge 在我桌面开着（端口 9222），
已登录 {网站URL}。之前通过 SSH 连接的 CC 已跑通 {N} 轮（10分钟间隔），
现在换你接手。

操作：
1. 杀掉所有旧的 auto_refresh 进程
2. 启动 CDP 保活：
   python auto_refresh.py --cdp --system {系统名} --interval 10
3. 确认第一轮通过

然后建一个 cron，每 10 分钟执行：
- 检查 keepalive_status.json 中的 {系统名} 状态
- 每轮都汇报，格式一行：
  ✅ R{N} {时间} | JWT {剩余分钟}分钟 | 正常
- 如果状态异常或 token 剩余 <30 分钟 → 展开详情，提醒我处理
```

### 3. 用户手动操作

1. 确认桌面 Edge 仍开着（端口 9222）
2. 将指令模板粘贴给本地 CC
3. 观察第一轮通过后即可回归正常使用

## 设计原理

| 层级 | 职责 |
|------|------|
| 桌面 Edge（用户启动） | GUI 权限 + 登录态持有者，独立于任何 CC 进程 |
| 本地桌面 CC | 长期 cron 监控 + 异常汇报，有桌面 session 不需要 CDP 也能弹窗 |
| SSH CC | 开发、验证、首次跑通即退出，不负责长期保活 |

关键认知：CDP 方案下，浏览器不归任何 CC 管。Edge 在桌面独立运行，登录态天然持久。CC 只是操控器，断了重连即可，不需要为"永不中断"设计过度方案。

## 已知限制

- 用户桌面 Edge 意外关闭 → 登录态丢失，需手动重启 Edge + 重新登录
- 本地 CC 的 cron 依赖 CC session 存活（最长 3 天），过期需重建
- 如需要真正的永久保活（不依赖任何 CC session），考虑 Hermes 侧 cron + SSH 直接执行脚本
