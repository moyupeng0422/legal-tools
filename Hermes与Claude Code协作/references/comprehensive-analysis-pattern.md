# 多工具整合分析的三维覆盖模式

> 用户要求将多个独立工具整合为复合 skill 时的标准分析框架。

## 触发条件

用户说类似"把这些工具整合成一个skill"时，必须执行三维分析，不能只讨论SKILL.md结构。

## 三维覆盖

### 维度1: 冗余分析
- 功能重叠：哪些工具做同一件事
- 删除建议：哪些可以移除，理由
- 合并/独立判断：功能重叠的是合并还是共存

### 维度2: 改造清单
- 每个工具当前存在的问题
- 数据源失效、配置缺失、功能不足
- 哪些必须修、哪些记录现状即可

### 维度3: 组合方案
- skill 目录结构（聚合层 + 子模块）
- 路由表/触发词映射
- 数据源依赖关系与降级链
- 已有 skill/MCP 工具的引用关系

## 执行顺序

1. Hermes 全面盘点工具清单（包括依赖库、已装 skill、MCP、cron）
2. CC 逐文件审查源码（通过 SSH 或下载包），不接受 Hermes 的摘要
3. CC 输出三维分析表
4. Hermes 独立评估 → 发回质疑 → CC 修正
5. 达成一致后 CC 执行创建完整 skill 包
6. Hermes 验证后传回云端部署

## 反面案例

用户纠正：「方案不仅仅只是建一个skill.md，包括这么多工具怎么搭配组合，哪些可以删除不要，哪些需要修改调整，这些都需要跟cc讨论。最后让cc来执行做一个完整，独立能用的完整skill。」
