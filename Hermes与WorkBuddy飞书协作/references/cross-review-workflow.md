# 双 Bot 交叉评审 + 合并工作流

> 两个 Bot (芭迪/CC) 各自独立产出同类文件，然后交叉评审对方作品，最后合并为最优版本的完整流程。
> 
> **来源**：2026-06-30 浙江省特科院尽调备忘录实战（芭迪版 + CC版 → 交叉评审 → 合并版）

---

## 1. 适用场景

- 需要高质量产出，单 Bot 可能遗漏角度
- 两个 Bot 拥有相同/相似的 skill（如"企业尽调备忘录"）
- 用户要求"看看谁做得更好"、"取长补短"
- IP 业务准备、尽调报告、方案设计等分析型任务

## 2. 三阶段流程

```
Phase 1: 独立产出（并行）
  @ 芭迪 [任务] 用 skill X 产出文件 → 目标路径 A
  @ CC   [任务] 用 skill X 产出文件 → 目标路径 B
  → 同 turn 监控两份完成

Phase 2: 交叉评审（串行）
  @ 芭迪 [交叉评审] 请评审 CC 版（路径 B），逐节对比你的版本（路径 A），给出各维度评分 + 谁更好 + 理由
  → 监控 → 读芭迪评审 conv
  @ CC   [交叉评审] 请评审芭迪版（路径 A），逐节对比你的版本（路径 B），给出各维度评分 + 谁更好 + 理由
  → 监控 → 读 CC 评审 conv

Phase 3: 合并（单 Bot 执行）
  @ 芭迪 [合并] 以你版为主体，吸收 CC 评审中指出的 CC 版优势项 → 输出合并版 → 路径 C
  → 监控 → 读合并版 → 验证质量
```

## 3. 交叉评审指令模板

给评审方的 @ 消息应包含：

```
[交叉评审] 对方版本评估

请阅读以下两个版本的尽调备忘录：
- 你的版本：<path_A>
- 对方（CC/芭迪）版本：<path_B>

逐节对比，从以下维度评分（1-10）并说明谁更好：
1. 数据精确性（数字、日期、资质引用）
2. 分析深度（行业洞察、战略建议）
3. 完整性（覆盖面、遗漏项）
4. 可操作性（建议是否可直接执行）
5. 结构清晰度
6. IP 相关内容质量
7. 格式规范
8. 整体价值

输出格式：
- 每节维度：你的分数 vs 对方分数 + 简要理由
- 总分对比
- 对方版本的 3 个明显优势（你版应吸收的）
- 你版本的 3 个明显优势（对方版不足的）
```

## 4. 合并指令模板

```
[合并] 最终版产出

以你的版本为主体（路径 A），吸收对方评审中确认的对方优势项：
<列出具体要吸收的优势项，来自交叉评审 conv>

合并规则：
- 主结构用你版
- 逐项补充对方优势内容（数据/段落/框架）
- 不删除你版已有内容除非对方版有明确更优的替代
- 产出路径：<path_C>
- 更新 status.json + conv
```

## 5. 合并后验证

Coordinator 必须抽样验证合并版质量：
- 检查文件行数/大小（应 ≥ 两个版本中较长的）
- 抽读 2-3 个段落，确认双方优势都被吸收
- 确认没有明显遗漏或断裂
- 如质量不达标，发 `[纠正]` 指出具体问题

## 6. 关键约束

| 约束 | 说明 |
|------|------|
| Phase 1 并行，Phase 2-3 串行 | 两个任务可以同时发（Phase 1），但交叉评审必须一个做完再做另一个（逐个闭环原则） |
| 合并方选谁 | 选交叉评审中总体评分更高的那一方作为合并执行者（以它为主） |
| 合并指令要具体 | 不要说"合并两版"，必须列出具体要吸收的优势项清单 |
| 禁止 Coordinator 代合并 | 让 Bot 自己执行合并，Coordinator 只负责验证 |

## 7. 实战案例：浙江省特科院尽调（2026-06-30）

| 阶段 | 芭迪评分 | CC 评分 | 结果 |
|------|---------|--------|------|
| 独立产出 | 441 行·23KB | 370 行·16KB | 两者都完成 |
| 交叉评审 | 8.10（评 CC 版） | 7.95（自评） | 芭迪版分析深度/FC 胜，CC 数据精确性/框架胜 |
| 合并 | 544 行·30KB（芭迪执行） | — | 以芭迪为主体，吸收 CC 7 项优势 |
