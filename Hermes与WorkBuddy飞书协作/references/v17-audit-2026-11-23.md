## CC 审核循环实战（PAUSE 机制首次发挥价值）

流程：TASK → CC PAUSE（拒绝虚审：要求贴协议全文+代码段落，并质疑 ts 参键）→ Hermes 答复质疑 + scp 补料 → CC 读码终审 DONE（抓出 P0-7 die 定性错误 + 确认核销连带 bug）→ Hermes 修复 → CC 再次读码复核 DONE 确认收口。

关键经验：
- **PAUSE 是质量闸门不是流程成本**：CC 拒绝虚审的坚持逼出了补料，间接抓出核销连带 bug
- **CC 要求「读码复核不采信通报」**：修复后必须让审核方重新拉代码验证，而非采信 Hermes 自报
- **小提醒也要回应**：CC 提的「close 按 task 匹配注意子串误删」（wm-1 vs wm-11）虽不阻塞但需确认 == 精确匹配后明确答复
