# 场景识别规则表（scenario-map · L1/L2 · 内置场景字典）

> 作用：总skill的**场景识别模块**——把用户需求逐层定位到功能组合。
> 层级：L1板块（6选1）→ L2场景（板块内4-5选1）→ 交接给场景子skill（或无子skill走通用流程）。
> L3子场景（每个L2下3-5个）**由场景子skill承载**，本表只到L2。
> 识别方式：**关键词规则表 + LLM兜底**（规则命中即定，未命中由LLM判断并记录依据）。
> **框架化定位（2026-08-21）**：本表是**内置场景字典**——路由表按 `data/user-profile.json` 动态生效：
> · 路由优先级：**custom 自定义场景（X1/X2/…）> enabled_L2 勾选场景 > 内置21场景兜底 > 通用流程**
> · `scenes.mode: "selective"` 时，未勾选场景命中 → 提示"该场景未启用，建议在 profile 中开启"后仍按兜底执行
> · 自定义场景（scenes.custom）最简只需 name + triggers + functions（功能1-9编号），无子skill 走通用流程
> 状态：⏳ **初稿占位**（2026-08-04）——随子skill落地逐步倒回去补充校准；**2026-08-14 F板块重构**（F1/F2/F3合并为F1咨询+L3复杂度分层，补功能3/6/7/9，标注hall_detect降级）；**2026-08-21 框架化**（内置字典化+profile动态路由）。

| **C 申请行政** | 商标注册、专利申请、近似、驳回、复审、无效宣告、撤销、备案、审查指南、国知局、商标局、审查意见 | 向行政机关申请/对抗行政程序 |

## 三、识别流程（总skill执行）

```
① 用户需求输入
② L1板块识别（规则表匹配 → 未命中LLM兜底）
③ L2场景识别（板块内匹配 → 未命中LLM兜底并记录）
④ 查子skill注册表（data/subskills-registry.json）：
   · 有专属子skill → 交接L2场景ID，启动子agent执行
   · 无专属子skill → 走通用场景流程（L2直接映射功能组合，见上表"功能组合"列）
   · 覆盖类型❌（B3/B4/C1/C2）→ 明确告知用户本skill无此数据源，建议专业MCP/企查查
   · 覆盖类型🔄（B1）→ 转调 company-investigation-memo
```
