# F1.2 深度咨询 · 研究备忘录层（layers/f1-2-memo.md）

> **判层线索**（骨架第一节详表）：陌生领域/跨领域、需搭知识框架、类案研究、**客户带具体案号来**。
> **分发模式**：标准分发（9 步全流程 + 6 要素）。Phase 总览见骨架第二节；本文件为 Phase 1-5 详解 + F1.2 输出模板 + 质量校验清单。F1.3 在本文件基础上另加载 `f1-3-opinion.md` 增量层。
> **覆盖约定提示**（骨架第四节 #1）：F1.2 关键结论（法条/案号）须 ≥2 独立数据源——法条交叉用 f1 卡交叉段（元典 rh_ft_detail，1分）；案号按 f3 卡免费层双源（矛盾/全空升级北大法宝 fulltext 25分）。方案设计时计入默认编排。

## 一、Phase 1-5 详解

### Phase 1：问题理解与拆解

**★ 退出检查**：如果用户的问题不涉及中国法律分析（如纯技术问题、非中国法律、纯事实查询），上报总skill 转路由，不强行进入检索流程。

这一步的目标是确保检索方向正确——方向错了，后面所有检索都是浪费。

**L3 定层**：按骨架第一节判断线索表确定 F1.1/F1.2/F1.3（判断不唯一取更深）。

**识别问题类型**：法条适用 / 侵权判定 / 权利范围 / 程序问题 / 合同交易 / 其他

**提取关键要素**：
- 涉及的法律领域（知识产权/合同/劳动/公司等）
- 具体法律概念或争议焦点
- 相关主体、行为、标的物
- 时间要素（影响时效性判断）

**制定检索计划**：确定主关键词和补充关键词，按速查卡功能维度规划检索组合与升级顺序，估算预算（衔接协议①方案设计的输入）。

**输出**：向用户展示问题理解摘要和检索计划，确认方向无误后继续。

### Phase 2：法律依据检索

这一步要回答"法律怎么规定的"。先定位核心法条原文，再补充相关法规。

**检索逻辑**（功能编排，执行顺序即省钱顺序）：
- **功能1法条精准起手**（确定型）——明确问题直接查，省钱；命中即提取法条原文，保证是现行有效版本
  ⚠️ 不命中/问题模糊 → 才走 **功能2语义兜底**（免费层法信/FLK LLM拆词 → 元典15分；北大法宝125分档留给深度场景，威科10次稀缺最后）
- **功能7时效核验**（确认引用法条现行有效，防引用失效版本）
- 补充法规检索走功能1/功能2 组合（法信法规库可覆盖 FLK 未收录的司法解释等）
- 对核心法规可用功能1的详情下钻获取完整结构，理解法条上下文

**F1.2 交叉验证（覆盖约定 #1 强制项）**：Phase 2 命中的关键法条（决定答复方向者），按 f1 卡交叉段用独立数据源交叉 1 次（元典 rh_ft_detail 1分；或路径内另一免费源）——与"确定型即停"不矛盾：即停=不重复检索同源，交叉=换独立源验证。

**知识产权案件**：加载 `references/ip-strategies.md` 获取预制检索策略（功能编号×检索词组）。

**关键原则**：
- 法条引用必须来自 MCP 检索结果，不凭记忆引用
- 引用法条后立即确认时效性
- 如果关键词没命中，尝试同义词或上位概念（同工具换词仅 1 次，再空即按路径升级——pitfall #34）

**输出**：立即向用户展示检索到的法律依据清单，标注核心法条和辅助法条。

### Phase 3：裁判规则与案例检索

这一步要回答"实践中怎么判的"。法律条文往往概括性强，裁判规则和案例能揭示具体适用标准。

**并行多源检索**——各源数据不同，互为补充：
- **功能5类案检索**（分析型规则：免费层多源能用几个用几个）：法信裁判规则（免费，20+维度）——理解法院对特定问题的裁判标准；免费层不足或存疑 → 按批准方案升级北大法宝（25分）/元典（5分）交叉校验
- **功能6权威案例**：RMFYALK 指导性/参考案例（官方库，免费）——获取权威判例；北大法宝 caseGrade 筛选（25分）按需升级
  ⚠️ **key_content 勿用 keyword**（pitfall #16）
- **功能3精准找案例**（仅当客户带具体案号）：按 f3 卡案号核验路径执行（免费层双源优先——RMFYALK+法信；矛盾或全空才升级北大法宝 fulltext 25分）；无案号则跳过
- **功能9法条下钻**（F1.2 陌生领域）：法信独有法条→案例/期刊下钻，搭知识框架（link_* 已修复验证可用）

**获取详情**（取最相关的 3-5 个）：
- 法信结果按 f5 卡详情下钻获取完整裁判规则（传 uniqid）
- RMFYALK 结果按 f6 卡获取案例详情（裁判要点、理由、关联法条，传 cpws_al_id）
- 指导性案例优先级高于参考案例——指导性案例对下级法院有约束力

**输出**：立即向用户展示检索到的裁判规则和典型案例。每条裁判规则须标注来源案例的案号和案例层级（指导性案例/参考案例/一般案例）。

### Phase 4：交叉校验与综合分析

这一步确保结论可靠。单源信息可能存在偏差或过时，交叉验证是质量保障的关键。

**过程性校验**（每完成一个争议点分析就检查，不是最后统一检查）：

| 校验项 | 检查时机 | 为什么要校验 |
|--------|---------|------------|
| 法条准确性 | 引用法条后立即核对 MCP 原文 | 记忆中的法条可能与现行版本有出入 |
| 法规时效性 | 引用法条后立即确认 | 引用已废止的法条会导致结论完全错误 |
| 裁判规则一致性 | 每个争议点分析完成时 | 不同来源对同一问题可能有分歧 |
| 案例层级 | 引用案例时标注 | 指导性案例 > 参考案例 > 一般案例 |

**分析框架**：

综合分析按争议焦点逐一展开，每个争议点严格遵循"争议问题→适用规则→适用分析→结论"结构（即 IRAC 框架）：

1. **争议问题**：该争议点的具体问题是什么
2. **适用规则**：援引法条原文和裁判规则
3. **适用分析**：将规则适用于本案事实，引用具体案例支撑。如有分歧如实呈现
4. **结论**：该争议点的判断，标注确定性

**为什么用这个框架**：这是法律分析的国际标准框架（IRAC，参考 Bloomberg Law, Columbia Law School），确保分析有结构、有依据、有逻辑链，避免跳跃式论证。

**不同观点处理**：对每个争议点，如果存在主流观点和反对观点，必须：
- 分别陈述各自的具体论点、法条依据、案例支撑
- 分析哪个观点更有说服力及原因
- 不选择性只呈现某一面

**[verify] 标记**：无法通过 MCP 确认的内容，用 `[verify]` 标记并说明原因。

### Phase 5：报告生成

**F1.2**：加载 `references/report-template.md` 获取完整输出模板（8章结构）；同时加载 `references/citation-url-rules.md` 获取引用来源 URL 构造规则。

**关键结构要求**（模板已内置）：
1. **结论先行**：研究问题后紧跟"简要结论"，让读者第一时间获得答案
2. **法条完整引用**：每条法条必须引用完整原文，不得截取片段
3. **案例论理链条**：每个案例必须分析法院的大前提→小前提→推理过程→关键论证
4. **IRAC 结构**：综合分析按争议焦点逐一展开（争议问题→适用规则→适用分析→结论）
5. **实务建议**：结论后附可操作的行动建议
6. **引用来源可跳转**：引用来源表中的每条记录须附详情页链接（按 citation-url-rules.md 构造 URL，仅覆盖实际命中的库）

**输出位置**：`D:\zhishiku\知识产权法律实务\002 研究文章\`

**文件名格式**：`法律研究-{{主题关键词}}-{{YYYYMMDD}}.md`

保存前确认文件名与用户。

## 二、F1.2 输出模板（8章报告，落盘）

```
一、研究问题 + 关键要素
二、简要结论（结论先行 + 确定性分级）
三、法律依据（法条完整原文 + 来源）
四、裁判规则（适用条件 + 来源案例表）
五、典型案例（含裁判理由论理链条：大前提/小前提/推理/关键论证）
六、综合分析（每焦点 IRAC 独立展开 + 不同观点梳理）
七、结论与建议（含实务建议）
八、引用来源表（含可跳转详情链接，按 citation-url-rules.md 构造）
```

## 三、质量校验清单（输出前自检）

报告生成后逐项自查：

- [ ] **法条准确性**：所有引用法条均通过 MCP 检索确认，非凭记忆引用
- [ ] **时效性**：引用的法律法规均为现行有效版本
- [ ] **来源标注**：每条法律依据和案例均标注了数据来源
- [ ] **案例层级**：优先引用指导性案例，其次参考案例
- [ ] **交叉验证**：关键结论至少有 2 个独立来源支持（覆盖约定 #1，F1.2 强制）
- [ ] **不确定标记**：无法确认的内容已用 `[verify]` 标记
- [ ] **问题回应**：报告完整回应了用户提出的所有问题
- [ ] **结论先行**：简要结论紧跟在研究问题之后，读者不需要读完整个报告就能获得答案
- [ ] **法条完整引用**：每条法条引用完整原文，没有截取片段
- [ ] **案例论理链条**：每个案例分析了法院的大前提→小前提→推理过程→关键论证
- [ ] **IRAC 结构**：综合分析中每个争议焦点按"争议问题→适用规则→适用分析→结论"展开
- [ ] **分歧如实呈现**：存在不同观点时，分别陈述并分析哪个更有说服力
- [ ] **实务建议**：结论后附有可操作的行动建议
- [ ] **引用来源可跳转**：引用来源表中每条记录附有详情页链接（按 citation-url-rules.md 构造，仅实际命中的库）

## 四、免责声明（随报告输出）

> ⚠️ 本报告基于公开法律数据库检索结果生成，受数据库覆盖范围、时效性和检索关键词限制。报告中的法律分析供研究参考，不构成法律意见。具体法律问题请结合案件全部事实和证据，由执业律师出具正式法律意见。
